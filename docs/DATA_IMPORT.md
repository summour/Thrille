# การนำเข้าตัวบทกฎหมาย

ขั้นตอนนำตัวบท ป.พ.พ. จริงเข้าโปรเจกต์ โดยแอปยังคง **offline-first**
ไม่มีการเรียก network ทั้งตอน build และตอนใช้งาน

## หลักการ

| ขั้น | ใครทำ | ต่อเน็ต |
|---|---|---|
| หาและคัดลอกเอกสาร | คุณ (ด้วยมือ) | ✅ ตอนเปิดเว็บ |
| แปลงเป็นโครงสร้างข้อมูล | `npm run import:law` | ❌ |
| แอปอ่านข้อมูล | Vite bundle | ❌ |

**ไม่มี scraper ในโปรเจกต์นี้** — ตามกฎ `AGENTS.md` §2.4

## ขั้นตอน

### 1. คัดลอกตัวบท

เปิด https://www.krisdika.go.th/ → ค้นหา "ประมวลกฎหมายแพ่งและพาณิชย์"
→ เปิดเอกสารฉบับปรับปรุงล่าสุด → คัดลอกเนื้อหา

บันทึกเป็น UTF-8 ทีละบรรพ:

```
data-source/raw/book1.txt   บรรพ 1 หลักทั่วไป
data-source/raw/book2.txt   บรรพ 2 หนี้
data-source/raw/book3.txt   บรรพ 3 เอกเทศสัญญา
data-source/raw/book4.txt   บรรพ 4 ทรัพย์สิน
data-source/raw/book5.txt   บรรพ 5 ครอบครัว
data-source/raw/book6.txt   บรรพ 6 มรดก
```

ไฟล์จะถูกอ่านเรียงตามชื่อ จึงต้องตั้งชื่อให้เรียงถูกลำดับ

### 2. กรอก manifest

แก้ `data-source/manifest.json` ระบุ URL, ชื่อเอกสาร, ฉบับแก้ไขล่าสุด และวันที่คัดลอก
ข้อมูลนี้จำเป็นสำหรับการตรวจสอบย้อนหลัง — **ห้ามข้าม**

### 3. รัน importer

```bash
npm install     # ครั้งแรกเท่านั้น (ติดตั้ง tsx)
npm run import:law
```

ผลลัพธ์:

```
▸ อ่านไฟล์ 6 ไฟล์: book1.txt, book2.txt, …
▸ ผลลัพธ์: 6 บรรพ · 312 หัวข้อ · 1755 มาตรา

  WARNING (3):
   ! เลขมาตราขาดช่วง 1246 → 1250 (ขาด 3 มาตรา)
   ! หมวด 4 ว่างเปล่า

✓ เขียนไฟล์แล้วที่ src/data/generated/
```

### 4. ตรวจและ commit

```bash
npm run typecheck && npm run dev
git add data-source src/data/generated
git commit -m "data: import ป.พ.พ. from krisdika (retrieved 2026-09-01)"
```

## รูปแบบไฟล์ดิบที่ parser รองรับ

```
บรรพ ๑
หลักทั่วไป

ลักษณะ ๑
บทเบ็ดเสร็จทั่วไป

มาตรา ๔ กฎหมายนั้น ต้องใช้ในบรรดากรณีซึ่งต้องด้วยบทบัญญัติใด ๆ
แห่งกฎหมายตามตัวอักษร หรือตามความมุ่งหมายของบทบัญญัตินั้น ๆ

เมื่อไม่มีบทกฎหมายที่จะยกมาปรับคดีได้ ให้วินิจฉัยคดีนั้นตามจารีตประเพณี

[มาตรา ๔ แก้ไขเพิ่มเติมโดยพระราชบัญญัติให้ใช้บทบัญญัติ…]
```

| องค์ประกอบ | รูปแบบที่รองรับ |
|---|---|
| หัวข้อ | `บรรพ ๑` / `ลักษณะ ๒` / `หมวด ๑` / `ส่วนที่ ๑` — ชื่อจะอยู่บรรทัดเดียวกันหรือบรรทัดถัดไปก็ได้ |
| มาตรา | `มาตรา ๑๕๐` · `มาตรา ๑๕๙๘/๑` · `มาตรา ๑๓๗๕ ทวิ` |
| ย่อหน้า | คั่นด้วยบรรทัดว่าง |
| หมายเหตุ | บรรทัดที่อยู่ในวงเล็บเหลี่ยม `[…]` |
| เลขไทย | แปลงเป็นเลขอารบิกอัตโนมัติ |
| ขยะจาก PDF | ตัด header/footer/เลขหน้าให้อัตโนมัติ (ดู `scripts/lib/clean.ts`) |

## ตัวเลือก

| คำสั่ง | ผล |
|---|---|
| `npm run import:law` | นำเข้าและเขียนไฟล์ |
| `npm run import:law:check` | ตรวจอย่างเดียว ไม่เขียน (ใช้ใน CI) |
| `npm run import:law -- --join=none` | ต่อบรรทัดแบบชิด (ใช้เมื่อ PDF ตัดคำกลางคำ) |

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `ORPHAN_ARTICLE` | มาตราอยู่ก่อนหัวข้อ `บรรพ` | เพิ่มบรรทัด `บรรพ ๑` ที่ต้นไฟล์ |
| `EMPTY_ARTICLE` | บรรทัด `มาตรา ๑๒๓` ถูกตัดจากเนื้อหา | ตรวจว่าไม่มีบรรทัดว่างคั่นทันทีหลังเลขมาตรา |
| `MISSING_TITLE` | ชื่อหัวข้ออยู่ห่างเกินไป | ย้ายชื่อให้อยู่บรรทัดถัดจากหัวข้อ |
| ตัวอักษรติดกันหมด | copy จาก PDF ที่ตัดคำ | ลอง `--join=none` แล้วเทียบผล |
| คำแปลก ๆ เช่น `ํา` | สระถูกแยก | บันทึกไฟล์ใหม่เป็น UTF-8 NFC |

## ข้อควรระวัง

- ตัวบทมีการแก้ไขเรื่อย ๆ — บันทึก `amendedThrough` และ `retrievedAt` ทุกครั้ง
- ผลลัพธ์ที่ได้ **ไม่ใช่** ฉบับทางการ ต้องเทียบกับราชกิจจานุเบกษาก่อนใช้อ้างอิงจริง
- ห้ามแก้ `src/data/generated/` ด้วยมือ — แก้ที่ `data-source/raw/` แล้ว import ใหม่
- ถ้า bundle ใหญ่เกิน ~2 MB ให้พิจารณาแยก JSON ต่อบรรพ + lazy-load
